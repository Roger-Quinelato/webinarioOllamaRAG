## 4. Um erro que a 1ª versão desta correção cometeu, e como foi pego

Traduzir "nome no requirements.txt" para "nome do módulo" não é trivial (`pillow` importa como
`PIL`). A 1ª versão usou `importlib.metadata.packages_distributions()` e pegou o **primeiro** módulo
mapeado para cada distribuição. Saída dessa versão:

Repare nas linhas 7, 11 e 14: `chromadb` virou o módulo `schemas`, e `ipykernel` e `matplotlib`
viraram `__pycache__`. Todas deram `[OK ]`. O script saiu 0 **sem ter importado nenhum dos três** —
a mesma classe de checagem muda que a auditoria condenou no eixo A2.

Por que acontece — nomes de topo que cada distribuição declara nesta `.venv`:

--- por que o mapeamento ingenuo falha: nomes de topo por distribuicao ---
  chromadb     -> ['chromadb', 'chromadb_rust_bindings', 'schemas']
  ipykernel    -> ['__pycache__', 'ipykernel', 'ipykernel_launcher']
  matplotlib   -> ['__pycache__', 'matplotlib', 'mpl_toolkits', 'pylab']
  ollama       -> ['ollama']
  pypdf        -> ['pypdf']
  shap         -> ['shap']
  numpy        -> ['numpy']
  pandas       -> ['pandas']
  streamlit    -> ['streamlit']
  httpx        -> ['httpx']

  import __pycache__ NAO levanta erro; __file__ = None
  (namespace package: diretorio sem arquivos importa em silencio -- e o modo de falha do A1-00)

--- pip check ---
No broken requirements found.
exit=0

Correção: a escolha do módulo prefere o candidato cujo nome bate com o da distribuição, e só depois
um candidato que não comece com sublinhado (`_`). É isso que faz `chromadb`, `ipykernel` e
`matplotlib` aparecerem com a versão certa na seção 1.

Há ainda um aviso de última linha para módulo importado como **namespace package**
(`__file__ is None`), que é o que torna `import __pycache__` um falso OK. Ele **avisa e não
reprova**, de propósito: existe namespace package legítimo (`google`, de protobuf; `opentelemetry`),
e reprovar um deles mandaria reinstalar um pacote sadio. A detecção de verdade do modo de falha do
A1-00 — `RECORD` apontando para arquivos que sumiram — é o ticket T37/#44.

## 5. Um defeito pré-existente, corrigido de passagem

A linha seguinte ao laço de imports era:

    if "ollama" not in falhas:

`falhas` guarda o **rótulo** da checagem (`"import ollama"`), nunca o nome do pacote, então a
condição era sempre verdadeira: com o import do `ollama` quebrado, o script seguia para o bloco do
servidor e trocava uma falha clara por um erro de import mais adiante. Agora `checar()` devolve o
resultado, o laço guarda os nomes em `imports_quebrados`, e a condição usa esse conjunto.
