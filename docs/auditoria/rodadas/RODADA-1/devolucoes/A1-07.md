1. **Erro:** o achado afirma que "a sobreposição efetiva fica em 142–149 caracteres". O intervalo está
   errado: ele é artefato do jeito como você mediu, não do comportamento de `dividir_texto`. A medição
   usou `b[:40]` como chave e procurou a **primeira** ocorrência dessa chave em `a` com `a.find(...)`;
   num texto sintético repetitivo (`palavra0 palavra1 …`), essa chave pode casar uma ocorrência
   anterior, encurtando o valor calculado. Além disso, a severidade está inflada: o achado trata como
   defeito um desvio de 1 caractere que existe por escolha explícita de projeto.

2. **Onde:** `rag.py:142-144`:
   ```python
   proximo = max(fim - sobreposicao, inicio + 1)
   espaco = texto.find(" ", proximo, fim)
   inicio = espaco + 1 if espaco != -1 else proximo
   ```
   O `espaco + 1` posiciona o início da parte seguinte **depois** do espaço, para nenhuma parte começar
   no meio de uma palavra. Uma sobreposição de exatamente 150 caracteres exigiria começar no meio da
   palavra em que o recuo caiu. O código escolhe a palavra inteira; o custo é um caractere.

3. **Evidência contrária:** repeti a medição com quatro textos de tamanhos diferentes (120, 260, 400 e
   900 palavras) e chave de 30 caracteres:
   ```
   == CTO/A1-07 sobreposicao: existe caso com sobreposicao zero ou palavra cortada? ==
     sobreposicoes observadas: min=149 max=149 zeros=0 (config=150)
     alguma parte termina no meio de uma palavra? False
   ```
   Valor constante em 149, nenhuma sobreposição nula, nenhuma palavra cortada.

4. **Como refazer:** antes de reportar qualquer número, repita a medição com uma segunda entrada de
   forma e tamanho diferentes — aqui, um texto **não repetitivo** teria mostrado 149 constante logo na
   primeira medição. Para medir sobreposição, não use `find` de uma chave curta num texto com padrões
   repetidos: compare os sufixos de `a` com os prefixos de `b` diretamente, ou instrumente os índices
   que `dividir_texto` calcula. E, antes de classificar como defeito, leia os comentários da região:
   `rag.py:137-144` deixa a intenção explícita. Se você quiser reabrir esta área, o alvo com valor real
   é diferente — verifique se existe alguma entrada em que a sobreposição chega a **zero** (perda de
   contexto entre chunks) ou em que `dividir_texto` entra em laço infinito; nenhuma das duas foi
   testada, e essas sim teriam impacto no retrieval.

5. **Critério de aceite:** um achado revisado sobre `dividir_texto` só será aceito se trouxer (a) a
   medição repetida em pelo menos duas entradas com formas diferentes, (b) uma consequência
   demonstrada no retrieval — chunk que perde contexto, resultado de busca que muda — e não apenas a
